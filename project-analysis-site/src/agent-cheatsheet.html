一句话定位

通用版

基于 Spring Boot 4 和 Spring AI 2.0 的 AI 面试训练平台：简历分析、文字与语音模拟面试、RAG 知识库问答、题库面试。核心价值是把慢、贵、不稳定的大模型调用做成可靠的产品：异步化、结构化输出重试、幂等、状态机、限流。

Agent 岗版

一个以工作流为主、在语音面试里带一个工具调用循环的大模型应用。我用最小实验验证了它工具循环的问题（工具回合丢失用户消息），找到了项目放弃工具调用的真正原因，并设计了带预算和循环上限的追问决策 Agent。

必须会画的图

  1. 三种交互方式：同步、异步（Stream）、流式（SSE / WebSocket）。
  2. 自主度光谱：L0 单次调用到 L4 多 Agent，项目各环节的位置。
  3. Advisor 链与两个循环：工具循环在外，校验循环在内。
  4. 工具回合的消息对比：默认配方只剩 SYSTEM 和 TOOL。
  5. 题库生成状态机 或 Stream 消费者循环。
  6. 面试官 Agent 架构：工具、边界、结构化决策、证据沉淀。

经过验证的 8 条结论

  1. 工具回合丢消息：默认配方关了 ToolCallingAdvisor 的内部历史又没有记忆 Advisor，第二轮只发 SYSTEM → TOOL；这很可能就是 4 月“工具调用不兼容”的根因（E1，A01）。
  2. 渐进式披露在这里是负收益：工具定义约 895 token，比任何一个技能正文都大，还要多一次往返（E2）。
  3. 摘要模板空转：占位符写成尖括号，变量不替换，开启压缩反而丢记忆（E3，A04）。
  4. 重试被放大：结构化调用最坏请求模型 8 次，指标只显示 2 次（E4，A03）。
  5. 护栏误伤：SafeGuard 扫描整个 Prompt，引用注入话术的正确回答会让整批评估得 0 分（E5，A02）。
  6. 循环没有上限：框架只看有没有 tool_calls，要自己加循环内侧的硬上限和工具预算（E6）。
  7. 记忆开关一开就坏：2.0 的记忆 Advisor 断言必须有会话 ID，项目从不传（A09）。
  8. 信任边界标反：可信人设被包进数据边界，与“边界内不执行指令”冲突（A06）。

10 个高频问题的 20 秒答案

问题20 秒答案展开
这是 Agent 吗？以工作流为主，语音有一个工具循环。定性小一点，分析深一点。AQ01
为什么大部分环节不用 Agent？结果要打分复用、时延和成本有预算、失败要能逐步重试；没有写工具，注入的最坏影响有限。总览
工具调用怎么工作？客户端驱动的多轮：带工具请求 → 模型返回 tool_calls → 执行后回填 tool 消息 → 带完整上下文再请求。模型不执行任何东西。协议层
怎么防止无限循环？工具层软预算 + 循环内侧的硬上限 Advisor + 重复调用检测，lab 里 16 次降到 4 次。E6
渐进式披露省 token 吗？看规模。这里索引 895 token 比正文还大，直接注入更省更快；技能多、正文长、会话有状态时才划算。Skills
记忆怎么做？文字面试会话双写、RAG 最近 10 条真实消息、语音文本拼接加窗口摘要；2.0 的记忆 Advisor 要传会话 ID、注意 order。记忆
JSON 怎么保证稳定？Schema 格式说明 + 校验循环 + 修复型重试 + 代码负责算术；要给重试设总预算。结构化输出
Prompt 注入怎么防？分层防御 + 输出只当数据 + 最小权限；关键词护栏会误伤，要移到输出侧。护栏
评估可信吗？有量表和基线，但评委人设错配、按位置对齐、没有金标集；用 MAE、±10 一致率、Spearman 做回归。LLM 评委
如果让你继续做？先修地基，再建尺子，最后给模型决策权：追问决策 Agent。路线图

不要说的话

  • “我做了一个 AI 面试 Agent。”除非你真的实现了追问决策 Agent，否则会被 Agent Loop、终止条件、评测三连问住。
  • “工具调用在多厂商之间不兼容。”这是项目文档的结论，而你已经有证据说明更可能是配置问题。
  • “渐进式披露一定省 token。”这个项目里恰好相反。
  • “SafeGuard 能防住注入。”它会误伤，也能被绕过，真正的边界在权限。
  • 任何没测过的数字（QPS、准确率、时延提升百分比）。
  • 把原作者和社区贡献者的设计说成自己独立完成的。
