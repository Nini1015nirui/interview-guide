    项目解析 · 总览

    InterviewGuide 智能面试平台：一份基于源码的项目拆解

    一个 Spring Boot 4 + Java 25 + Spring AI 2.0 + React 18 的全栈 AI 应用，覆盖简历分析、文字与语音模拟面试、RAG 知识库问答、知识库题库面试、面试日程和多模型管理。本站按模块拆开它的设计取舍、可靠性手段和真实演进过程，再整理成面试可以直接使用的问答、简历写法，以及一条用 Claude Code 从零复刻它的路线。面 Agent 应用开发岗的读者，另有一组 Agent 专题：用 Agent 的尺子重新审视项目，并用 8 个可复现的源码实验验证框架的真实行为。

    源码基线：commit b2d1ca0（2026-08-14） 102 次提交 · 6 位贡献者 17 页 · 全站精读约 4 小时

    一句话定位

    InterviewGuide 把“准备面试”拆成几个环节，并在每个环节用大模型替代人工：先让 AI 审简历，再按岗位方向或 JD 出题做模拟面试（可以打字，也可以实时语音对话），面试结束后异步生成评分报告；自己的学习资料上传成知识库后，既能做 RAG 问答，也能自动生成带参考答案和评分规则的题库，再从题库里抽题面试；最后用日历管理真实的面试安排。

    从工程角度看，它的价值不在功能数量，而在于怎么把“慢、贵、不稳定”的大模型调用变成一个可靠的产品：异步化、结构化输出重试、幂等、状态机、恢复调度、限流、Prompt 注入防御、实时语音链路里的并发与时序控制。这些正是面试里最容易被深挖、也最能拉开差距的部分。

    30 秒版本（面试开场可以直接用）

    这是一个基于 Spring Boot 4 和 Spring AI 的 AI 面试训练平台，支持简历分析、文字和语音模拟面试、RAG 知识库问答和题库面试。后端用 PostgreSQL + pgvector 同时做业务库和向量库，用 Redis Stream 把简历分析、向量化、面试评估、题库生成这五类耗时任务异步化，并配了 pending 回收和定时恢复；大模型接入层支持多 Provider 热切换，结构化输出统一带修复型重试。我重点负责/深入研究的是（按你的实际情况填写）……

    项目档案

    形态
    前后端分离：单体 Spring Boot 后端 + React 单页应用；开源协议 AGPL-3.0
    后端
    Spring Boot 4.1.0 · Java 25（开启虚拟线程）· Spring AI 2.0.0 · spring-ai-agent-utils 0.10.0 · Gradle 9.6.1（版本目录 libs.versions.toml）
    数据与存储
    PostgreSQL 16 + pgvector（1024 维，HNSW 索引，余弦距离）· Flyway 管理表结构，Hibernate 只做 validate · RustFS / MinIO（S3 协议）存原始文件
    中间件
    Redis 7 + Redisson 4.0：会话缓存、分布式锁、Stream 消息队列、Lua 限流
    AI 能力
    OpenAI 兼容协议接入 DashScope（通义）、DeepSeek、Kimi、GLM、LM Studio；DashScope SDK 接入 Qwen3 实时语音识别与合成（WebSocket）
    文档处理
    Apache Tika 2.9 解析 PDF / DOC / DOCX / TXT / Markdown · iText 8 导出 PDF（内嵌中文字体）
    前端
    React 18.3 · TypeScript 5.6 · Vite 5 · Tailwind CSS 4 · React Router 7 · react-virtuoso · react-big-calendar · Recharts
    规模
    后端 197 个 Java 文件约 2.5 万行；前端 85 个 TS/TSX 文件约 1.8 万行；36 个测试类约 8 千行；17 个 Prompt 模板；10 个面试方向 Skill；16 张表；5 条异步任务管线
    部署
    Docker Compose 一键启动 6 个服务（前端 Nginx、后端、PostgreSQL、Redis、MinIO、建桶初始化任务）；GitHub Actions 跑前后端测试与构建

    三种交互方式

    整个系统的请求可以归成三类，理解了这三类，大部分设计就能对上号：同步请求只做快且确定的事；凡是要调大模型并且结果不必立刻拿到的，都走异步任务；必须边生成边展示的，走流式通道。

    最值得讲的技术点

    如果面试只有十分钟讲项目，从下面挑两到三个最熟的讲深，比把功能列表念一遍有用得多。每一条都对应源码里真实存在的实现和提交记录。

    • 多模型注册表与三种调用配方：Provider 配置存数据库（Key 用 AES-GCM 加密），按“默认 / 纯净 / 语音”三种 ChatClient 缓存，底层模型实例按 Provider 共享，设置页修改后热加载。见 AI 底座。
    • 结构化输出的统一重试：所有需要 JSON 的调用走同一个执行器，失败后把上次的错误原因截断后注入“修复型提示词”再试，还能在本地修复未转义的引号。见 AI 底座。
    • Redis Stream 异步模板：生产者、消费者用模板方法抽象，五条管线共用；消费前先回收超时的 pending 消息，失败重新入队最多 3 次，再加定时恢复任务兜底。见 可靠性。
    • 题库生成状态机：taskId 当围栏令牌，状态迁移全部在行锁内做比较再更新，旧任务的结果直接丢弃，新题替换和“完成”状态在同一个事务里提交。见 可靠性。
    • 多维限流的原子性：一个接口上叠加全局、IP、用户多条规则，一次 Lua 调用里先只读检查全部维度，全部通过才统一扣减。见 可靠性。
    • 刷新不重复出题：幂等键放在 URL 里，后端用分布式锁、Redis 结果映射和数据库唯一索引三层保证同一个请求只生成一次题目。见 可靠性。
    • 向量化的影子写入：重新向量化时新向量先带临时标记写入，检索看不到；全部成功后在一个事务里删旧、提升新，失败只清理临时数据。见 业务模块。
    • 实时语音链路：手动提交代替自动断句、三层回声防护、迟到字幕隔离、LLM 流式输出按句切分并发合成、按序号有序下发音频。见 语音面试。
    • Prompt 注入三层防御：输入净化加随机分隔符、系统提示词声明数据边界、请求前 SafeGuard 关键词闸门，外加“模型输出只当数据用”。见 AI 底座。

    面 Agent 岗时，下面三条是本站实验验证过、别人很少讲得出的内容：

    • 工具调用“不兼容”的真正原因：默认配方关掉了 ToolCallingAdvisor 的内部历史又没有记忆 Advisor，工具回合的第二轮只发系统消息和工具结果。见 源码实验 · 根因复盘。
    • 渐进式披露的真实成本：Skill 工具定义约 895 token，比任何一个技能正文都大。见 机制拆解 · Skills。
    • 护栏误伤与重试放大：引用注入话术的正确回答会让整批评估得 0 分；一次结构化调用最坏请求模型 8 次。见 Agent 专项发现。

    写作依据是完整阅读仓库源码（后端、前端、测试、配置、迁移脚本、Prompt、Skill 文件）、全部 102 条提交说明、.claude/tdd 下的 4 份 TDD 证据文档和 docs/testing 下的 2 份测试记录。Agent 专题另外对照了 Spring AI 2.0.0、2.0.0-M4 和 spring-ai-agent-utils 0.10.0 的框架源码，并在与项目相同的版本上运行了 8 个最小实验。文中提到的类名、配置项和数值都以 commit b2d1ca0 为准；提交号用虚线框标出，方便你回到仓库核对。

    诚实使用

    InterviewGuide 是公开的开源项目（原作者 Guide，AGPL-3.0），不少同学拿它做项目经历，面试官很可能见过。把它写进简历时，要讲清楚你自己的理解、改动和取舍，不要把全部设计说成独立完成。简历与讲述 一页专门讲了怎么讲出差异化，代码审查发现 里的问题可以作为你亲手改进的切入点。
